# Indian Food Vision AI

Upload a plate of food, snap it from your webcam, or drop in a JPG — and
get back the dish name, a confidence score, and a full macro-nutrition
breakdown. Tuned for Indian cuisine, with optional multi-item detection
and portion estimates when an AI vision LLM is configured.

Built end-to-end: a FastAPI backend with a three-layer recognition
pipeline, a ready-to-go training pipeline for custom images, a
nutrition database covering 50 popular dishes, and a dark-themed React
frontend with drag-drop, webcam capture, macro charts and scan history.

---

## What's inside

- **Three-layer recognition pipeline**
  - `EfficientNet-B0` fine-tuned on your own Indian food images
  - `CLIP` zero-shot fallback — works right away without any training
  - Optional **AI Vision** enhancement (external multimodal LLM) for
    multi-item detection and smarter portion estimates
- **Training pipeline wired to the bundled `train/` and `val/` folders**
  — 20 classes, ~3,900 training images, ~1,250 validation images
- **Nutrition database** covering 50 Indian dishes with calories,
  protein, carbs, fat and typical serving sizes
- **Polished frontend**: drag-drop uploader, webcam, macro donut chart,
  alternative guesses, multi-item table, scan history in a drawer
- **Zero hardcoded secrets** — all configuration is read from `.env`

## Quick start

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt

# (optional) enable the AI vision enhancement
cp .env.example .env
# open .env, paste an API key in AI_VISION_API_KEY=

uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Then open:

- API docs: <http://localhost:8000/docs>
- Healthcheck: <http://localhost:8000/api/health>

> First run downloads the CLIP model (~150 MB) into the Hugging Face
> cache. Every subsequent run uses the cache.

### 2. Frontend

```bash
cd frontend
cp .env.example .env                # optional — override VITE_API_URL
npm install
npm run dev
```

Open the app at <http://localhost:5173>.

## Training on your own images

The project ships with 20 labelled classes ready to train on. The
existing `train/` and `val/` folders at the project root contain around
3,900 training images and 1,250 validation images across:

```
burger, butter_naan, chai, chapati, chole_bhature, dal_makhani,
dhokla, fried_rice, idli, jalebi, kaathi_rolls, kadai_paneer, kulfi,
masala_dosa, momos, paani_puri, pakode, pav_bhaji, pizza, samosa
```

### Kick off a training run

```bash
cd backend
source .venv/bin/activate
python training/train.py --epochs 15 --batch-size 32
```

That writes two artefacts:

- `backend/checkpoints/best_model.pth` — best EfficientNet-B0 weights
- `backend/app/data/class_map.json` — class index → name map

The running backend picks both files up automatically when it next
starts.

### Dropping **new** images

```
train/<class_name>/your_image_001.jpg
val/<class_name>/your_image_017.jpg
```

Use **snake_case** folder names that match the keys in
`backend/app/data/nutrition_db.json` (e.g. `butter_chicken`, not
`Butter Chicken`). If you add a brand-new dish, add a matching entry to
`nutrition_db.json` — otherwise the backend will classify it but the
nutrition card falls back to the closest alias.

### More trainer flags

```bash
# Freeze the backbone — only trains the final layer, ~4× faster
python training/train.py --freeze-backbone --epochs 8

# Ignore val/ and auto-split from train/ (80/20 by default)
python training/train.py --no-val-dir --val-split 0.2

# Force CPU
python training/train.py --device cpu --batch-size 16

# Dataset sanity check (counts + corruption scan)
python training/prepare_data.py inspect --data-dir ../train --check-corrupt
```

Full flag reference lives in `backend/training/README.md`.

## How a prediction is made

```
            ┌────────────────────────────────────────┐
            │              POST /api/predict         │
            └────────────────────────────────────────┘
                             │
                             ▼
            ┌────────────────────────────────────────┐
            │ 1. Validate upload, decode with Pillow │
            └────────────────────────────────────────┘
                             │
            ┌────────────────┼────────────────┐
            ▼                ▼                ▼
   ┌────────────────┐┌───────────────┐┌──────────────────┐
   │ Custom model   ││ CLIP zero-    ││ AI Vision LLM    │
   │ (if trained)   ││ shot fallback ││ (if API key set) │
   └────────────────┘└───────────────┘└──────────────────┘
            │                │                │
            └────────────────┼────────────────┘
                             ▼
            ┌────────────────────────────────────────┐
            │ 2. Pick the strongest answer.          │
            │    Vision LLM wins above 0.5; else     │
            │    highest-confidence local pick.      │
            └────────────────────────────────────────┘
                             │
                             ▼
            ┌────────────────────────────────────────┐
            │ 3. Nutrition lookup + portion scaling  │
            └────────────────────────────────────────┘
                             │
                             ▼
                 PredictionResponse (JSON)
```

Every layer is optional. With no training and no vision API key, the
CLIP fallback still gives reasonable accuracy against the 50 dishes in
the nutrition DB. Add training for better accuracy on *your* data. Add
an AI vision key for multi-item plates and portion estimates.

## API reference

### `POST /api/predict`

Multipart body with a single `file` field (JPG / PNG / WebP, ≤ 10 MB).

**Response** (trimmed):

```json
{
  "success": true,
  "primary": {
    "dish_name": "Biryani",
    "confidence": 0.92,
    "source": "ai_vision",
    "is_indian": true
  },
  "alternatives": [
    { "dish_name": "Pulao", "confidence": 0.08, "source": "clip_zero_shot" }
  ],
  "nutrition": {
    "per_100g":   { "calories": 290, "protein": 12, "carbs": 30, "fat": 14 },
    "per_serving":{ "calories": 870, "protein": 36, "carbs": 90, "fat": 42, "serving_size_g": 300 },
    "items": [
      { "name": "Biryani", "portion_g": 300, "nutrition": { "calories": 870, "protein": 36, "carbs": 90, "fat": 42 } }
    ],
    "total":      { "calories": 870, "protein": 36, "carbs": 90, "fat": 42 }
  },
  "sources_used": ["custom_model", "clip_zero_shot", "ai_vision"],
  "processing_time_ms": 612,
  "notes": "Hyderabadi-style chicken biryani with caramelised onions."
}
```

### `GET /api/health`

Returns the backend version and which backends are live:

```json
{
  "status": "ok",
  "version": "1.0.0",
  "models": {
    "custom_model": true,
    "clip_zero_shot": true,
    "ai_vision": true,
    "nutrition_entries": 50
  }
}
```

### `GET /api/classes`

Lists every dish the nutrition DB knows about.

## Environment variables

### `backend/.env`

| Variable | Default | Notes |
| --- | --- | --- |
| `AI_VISION_API_KEY` | *(unset)* | Enables the AI vision enhancement. Optional. |
| `AI_VISION_MODEL` | *(unset)* | LLM model id for the vision provider. |
| `AI_VISION_ENDPOINT` | *(unset)* | HTTPS endpoint for the vision provider. |
| `AI_VISION_API_VERSION` | *(unset)* | API version value (sent as an HTTP header). |
| `AI_VISION_API_VERSION_HEADER` | *(unset)* | Name of the version HTTP header. |
| `AI_VISION_TIMEOUT_S` | `30.0` | Per-request timeout for the vision LLM. |
| `MODEL_CHECKPOINT_PATH` | `checkpoints/best_model.pth` | Relative to `backend/`. |
| `CLASS_MAP_PATH` | `app/data/class_map.json` | Written by the trainer. |
| `NUTRITION_DB_PATH` | `app/data/nutrition_db.json` | Macros DB. |
| `CLIP_MODEL_NAME` | `openai/clip-vit-base-patch32` | Any CLIP checkpoint on HF Hub. |
| `USE_CLIP_FALLBACK` | `true` | Disable to run with the custom model only. |
| `MAX_UPLOAD_SIZE_MB` | `10` | Rejects larger uploads with HTTP 413. |
| `ALLOWED_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173,http://localhost:3000` | Comma-separated CORS list. |

### `frontend/.env`

| Variable | Default | Notes |
| --- | --- | --- |
| `VITE_API_URL` | `http://localhost:8000` | Where the React app sends requests. |

## Tech stack

| Layer | Pick | Why |
| --- | --- | --- |
| Model | EfficientNet-B0 (fine-tune) | 5M params, fast on CPU, strong on small datasets |
| Zero-shot fallback | OpenAI CLIP (`clip-vit-base-patch32`) | Works with zero training, ~150 MB |
| Vision enhancement | External multimodal LLM via HTTPS | Multi-item scene understanding + portion estimates |
| Backend | FastAPI + Uvicorn | Async, auto OpenAPI docs |
| Image decoding | Pillow | Handles JPG/PNG/WebP cleanly |
| ML runtime | PyTorch 2.4 + torchvision | Mature, well-supported |
| HTTP client | httpx | Clean sync client for the vision API |
| Frontend framework | React 18 + Vite | Fast dev loop |
| Styling | Tailwind CSS 3 | Dark design system in a few tokens |
| Charts | Recharts | Donut chart for macros |
| Camera | react-webcam | Cross-browser getUserMedia wrapper |
| Drag-drop | react-dropzone | Battle-tested uploader |
| Animations | framer-motion | Polished entrance transitions |
| Icons | lucide-react | Clean, consistent icon set |

## Troubleshooting

**"No prediction backend produced a result"**
→ No checkpoint, no vision key, and CLIP failed to load. Either train a
model, set an API key, or make sure `torch` + `transformers` installed
correctly.

**`pip install` chokes on torch**
→ PyTorch wheels are platform-specific. On Apple Silicon the default
works. On Linux with CUDA, use the selector at
<https://pytorch.org/get-started/locally/> then re-run
`pip install -r requirements.txt`.

**CLIP is slow on the first request**
→ It's downloading `openai/clip-vit-base-patch32` (~150 MB) to the
Hugging Face cache. Subsequent requests use the cache and are fast.

**Webcam shows a black screen**
→ The browser needs an HTTPS origin *or* `localhost`. Grant camera
permission when prompted.

**Training crashes with `CUDA out of memory`**
→ Drop `--batch-size` (try 16, then 8) or use `--device cpu`.
